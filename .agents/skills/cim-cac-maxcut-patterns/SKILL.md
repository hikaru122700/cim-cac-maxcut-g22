# CIM / CAC MAX-CUT Patterns

Research codebase for Ising-machine heuristics (Coherent Ising Machine, Chaotic
Amplitude Control, Simulated Bifurcation, Simulated Annealing) solving MAX-CUT on
G-set / K2000 instances. **Windows-only** (see AGENTS.md). Python + NumPy + Numba +
Optuna + matplotlib, managed with `uv`.

> Most git commits are auto-generated by `auto_push.sh` (`auto: <timestamp> (N files)`),
> so commit messages carry no convention signal. The real conventions live in the
> **directory layout, the results-versioning rule, and recurring code idioms** below.

## Directory Architecture

```
modules/        # Algorithm implementations — the importable library
                #   CIM.py, CAC.py, SB.py, SA.py, PT_ICM.py, rulebase.py, verify.py
                #   Plus dated experiment variants: 2026-06-06_CIM_PT_v3.py
scripts/        # Executables, grouped by purpose:
  benchmarks/   #   compare/aggregate methods across graphs (benchmark_gset.py)
  tuning/       #   Optuna parameter search (tune_cim_pt_optuna.py)
  plotting/     #   visualization & diagnostics (plot_*, trace_*, diag_*)
  runners/      #   one-off run drivers
  utils/        #   helpers (md_to_pdf.py, generate_k2000.py, download_*)
input/          # Benchmark inputs (G-set, K2000) — Gset text format
results/        # ★ All outputs — date × kind × version (see below)
papers/         # Reference paper PDFs
docs/           # Algorithm notes & design memos (.md, often → .pdf)
tests/          # pytest unit tests for pure logic
```

Library code lives in `modules/` and is imported; everything runnable lives in
`scripts/<category>/`. Prefer **many small, focused files** over large ones.

## Results Versioning (the single most important rule)

Every artifact (PNG / JSON / CSV / DB / HTML / .npz) is saved under a **3-tier**
path. **Never overwrite** — auto-increment the version instead.

```
results/<YYYY-MM-DD>/<EXPERIMENT_KIND>/v{N}_<description>/<file>
```

- `<YYYY-MM-DD>` — run date, `date.today().isoformat()`.
- `<EXPERIMENT_KIND>` — a fixed `snake_case` constant per script: `EXPERIMENT_KIND = "cim_pt_optuna"`.
- `v{N}_<description>` — version auto-numbered **per kind** (resets each day/kind),
  description built from CLI args (`v1_g22_300trials_5var`). Support a `--tag` suffix.
- **Filenames carry no experiment/graph prefix** — that's the folder's job.
  Good: `cim_pt_optuna/v1_g22_300trials_5var/history.png`. Bad: `v1_g22_history.png`.

The canonical helpers (copy these verbatim into new scripts):

```python
EXPERIMENT_KIND = "my_experiment"

def next_version(kind_root: Path) -> int:
    max_v = 0
    if kind_root.exists():
        for p in kind_root.iterdir():
            if p.is_dir() and p.name.startswith("v"):
                head = p.name.split("_", 1)[0]
                if head[1:].isdigit():
                    max_v = max(max_v, int(head[1:]))
    return max_v + 1

kind_root = ROOT / "results" / date.today().isoformat() / EXPERIMENT_KIND
v = next_version(kind_root)
out_dir = kind_root / f"v{v}_{'_'.join(desc_parts)}"
out_dir.mkdir(parents=True, exist_ok=True)
```

Only date folders and **permanent assets** (`benchmark_gset.csv`, `optuna_*.db`)
may sit directly under `results/`.

## Script Bootstrap

All scripts are run **from the project root**: `uv run python scripts/<cat>/<name>.py`.
Relative paths (`input/G22.txt`) assume CWD = root. Every script inserts the root on
`sys.path` so `modules.*` imports resolve:

```python
ROOT = Path(__file__).resolve().parents[2]   # scripts/<cat>/<file>.py → root
sys.path.insert(0, str(ROOT))
from modules.CIM import build_coupling_matrix, load_graph, simulate_cim_batch
```

**Date-prefixed module files** can't be imported by name — load them with importlib:

```python
_PT_PATH = ROOT / "modules" / "2026-05-29_CIM_PT.py"
_spec = importlib.util.spec_from_file_location("cim_pt_mod", _PT_PATH)
cim_pt = importlib.util.module_from_spec(_spec)
_spec.loader.exec_module(cim_pt)
simulate_cim_pt_batch = cim_pt.simulate_cim_pt_batch
```

## Numba JIT Solver Pattern

Hot simulation loops follow a strict **private-core / public-wrapper** split:

- Private `_simulate_*(...)` decorated `@njit(cache=True, fastmath=True, parallel=True)`.
  Takes **only primitives + raw arrays** (CSR triplet `J_data, J_indices, J_indptr`,
  `edge_a, edge_b, edge_w`, scalars cast to `float`). `prange` over `num_trials`
  (trials are independent → race-free). Seed per-trial with `np.random.seed(seeds[t])`
  for reproducibility. Hand-write the CSR matvec and fuse per-element steps into one
  loop to skip NumPy ufunc / scipy wrapper overhead.
- Public `simulate_*_batch(n, J, edges, ..., seeds, weights=None)` — converts the CSR
  matrix and edge lists to contiguous typed arrays, casts scalars, calls the core, and
  returns `(best_cuts, best_signs)`.

Common helpers in `modules/CIM.py`, reused everywhere:
`load_graph` (Gset format, **1-indexed → 0-indexed**, optional 3rd weight column),
`build_coupling_matrix` (CSR, antiferromagnetic `J_ij = coupling·w_ij`),
`amplitudes_to_solution` (sign → 0/1). Always cross-check results with
`modules/verify.py` (`run_all_checks`, `compute_cut_from_edges`) — an independent
re-implementation used as an oracle.

## Optuna Tuning Pattern

`scripts/tuning/*` share a consistent shape:

- A `suggest_*` function proposes the search variables (`trial.suggest_float(..., log=True)`
  for physical scales). A `make_objective(...)` closure captures fixed graph/config and
  returns `objective(trial)`. Stash extra metrics with `trial.set_user_attr(...)`.
- **Warm-start with paper values** via `study.enqueue_trial({...})` on the first trial.
- **Resumable**: `optuna.create_study(storage=f"sqlite:///{(out_dir/'optuna.db').as_posix()}",
  load_if_exists=True)`, compute `remaining = N - len(study.trials)`. Add `--run-dir`
  to resume an existing output dir.
- `TPESampler(seed=0)`, `optuna.logging.set_verbosity(WARNING)`, a progress callback
  every 25 trials, and wrap the sim in `try/except` returning `0.0` on failure.
- Outputs per study: `best_params.json` (+ fixed params + provenance like `known_best`,
  `prev_mean`), `history.png` (per-trial scatter + running-best + reference lines),
  `importance.png` (fANOVA), and a top-level `summary.json`.

## Plot Style (project-wide, enforced)

Set at the top of any plotting code:

```python
import matplotlib
matplotlib.use("Agg")                              # headless save
import matplotlib.pyplot as plt
plt.rcParams["font.family"] = "Yu Gothic"          # Japanese labels (Windows)
plt.rcParams["axes.unicode_minus"] = False         # avoid "−" mojibake
...
ax.tick_params(direction="in", which="both", top=True, right=True)  # inward ticks, all sides
```

Labels, titles, and legends are written in **Japanese**. CIM amplitude plots use
y-axis `In-phase amplitude (arb.)`, x-axis `round step`, no legend.

## wandb Stub for Benchmarks

Solver modules import `wandb`, but batch benchmarks don't want logging. Install a
lightweight stub **before** importing the solvers:

```python
class _WandbStub:
    def init(self, *a, **k): self.config = ...; self.summary = {}; return self
    def log(self, *a, **k): pass
    def finish(self, *a, **k): pass
sys.modules.setdefault("wandb", _WandbStub())
import wandb  # noqa: E402
from modules.CIM import simulate_cim_batch  # noqa: E402
```

## Documentation & Comments Convention

- Module/function **docstrings are in Japanese**, and physics code cites the source
  paper's equation numbers inline (`Eq.(3)`, `Eq.(14)`) with the parameter glossary.
- A module docstring header typically states: the paper reference, a physical-intuition
  block, and the key parameters with units.
- Files default to UTF-8; cp932 console mojibake is tolerated (Windows-only project).

## Testing Convention

- **pytest**, in `tests/`. Tests exercise **pure logic only** — the heavy
  `simulate_*_batch` cores are not invoked; build small fixtures / fake `EvalResult`s.
- Verify **immutability**: e.g. `apply_override` must return a *new* config, never
  mutate the input (config objects are `@dataclass(frozen=True)` style).
- `from __future__ import annotations` at the top; import the unit under test from its
  `scripts.tuning.*` / `modules.*` path.

## CLI Convention

`argparse` with a Japanese `description`; standard options include the graph
(`--graph input/G22.txt`), trial/round counts, `--tag` (extra folder suffix), and
`--run-dir` (resume). Build the results description string from these args.

## When Adding New Work — Checklist

- [ ] New algorithm → `modules/<Name>.py`; new runnable → `scripts/<category>/`.
- [ ] Define `EXPERIMENT_KIND`; save under `results/<date>/<kind>/v{N}_<desc>/`, never overwrite.
- [ ] Bootstrap `ROOT = parents[2]` + `sys.path.insert`; run from project root.
- [ ] Hot loop → private `@njit` core + public `*_batch` wrapper, `seeds` for reproducibility.
- [ ] Cross-validate cuts against `modules/verify.py`.
- [ ] Plots: Agg, Yu Gothic, `unicode_minus=False`, inward ticks, Japanese labels.
- [ ] Optuna: warm-start paper values, sqlite resume, save `best_params.json` + `history.png` + `importance.png`.
- [ ] Tests for pure logic only; assert immutability.
