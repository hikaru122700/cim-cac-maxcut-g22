# Stage 18: Peer Review

# Peer Review — *DiPS: Do Learned Pump Schedules Beat a Sigmoid Ramp in CIMs?*

**Meta-summary (shared across reviewers).** The paper is well-written and addresses a genuinely interesting question with a clean experimental philosophy (compute-matched, separating the *schedule* axis from the *dynamics* axis). However, when the manuscript is checked against the supplied experiment evidence, it exhibits a **fatal claim–evidence breakdown**: the central quantitative claim of the abstract and Table 2 is contradicted both by the raw `results.json` and by the paper's *own* Table 4. Several core methodological claims (backpropagation/autodiff, external reference cut, G-set evaluation, integration steps) do not match the actual code. These are not cosmetic issues. The consensus recommendation is **Reject / Major Revision with re-run**, with the path to acceptance being an honest rewrite around what the data actually show.

I structure the detailed review as three reviewer personas, then a consolidated pass over the eight requested checks.

---

## Reviewer A — Methodology Expert

### Strengths
- The conceptual framing is excellent: explicitly decomposing the problem into a *solver axis* (dynamics/feedback) and a *schedule axis* (open-loop pump shape), and treating CAC as a reference arm rather than a competitor, is the right way to avoid the confound that "richer schedule = more compute." This is the paper's best idea.
- The compute-matched protocol (equal budget $B$ of full rollouts as the shared unit across Adam, CMA-ES, and TPE) is principled and well-motivated.
- Pairing every gradient-learned schedule with a gradient-free twin on the *identical* parameterization is a genuinely clean way to isolate "does the gradient buy a better basin."
- Held-out transfer split and the stated integrity gates (dt-halving, shape-null band) show good methodological instinct.

### Weaknesses (critical)
1. **"Differentiable rollout / backpropagation" is contradicted by the code.** The abstract, Introduction, and Method repeatedly claim the schedule is trained "by backpropagation through the simulated trajectory" via "reverse-mode automatic differentiation" (Algorithm 1: "Adam, reverse-mode autodiff"). The actual `main.py` docstring states optimization is **"Adam on a finite-difference gradient through the fixed-noise rollout."** Finite differencing is *not* differentiable simulation, and the entire branding — *DiPS = Differentiable Pump Scheduling* — rests on a mechanism the code does not implement. This invalidates the headline methodological contribution as written.
2. **Hyperparameters in Table 1 do not match the code.** Paper says $T=1000$ Heun steps; code says $T=100$. Paper says freeform = 32 knots; code says a 12-knot Catmull-Rom spline. Paper says SpecNet uses top-16 Laplacian eigenvalues into a 2×64 MLP; code says a 6→32→32→12 tanh MLP over 6 spectral features. None of these can be reconciled; a reader could not reproduce the reported runs.
3. **The "external best-known reference cut" claim is false.** Section 3 makes a methodological selling point that $C^\star$ is "an external best-known reference cut … rather than a quantity recomputed from the run itself, which removes the endogenous-reference bias." The code computes $C^\star$ as the **"pooled best cut across all conditions/seeds per graph"** — i.e., precisely the endogenous reference the paper claims to have eliminated. This is self-refuting and materially affects every gap number.
4. **Integrity gates are asserted but absent from evidence.** The dt-halving "≥80% of advantage must survive" check and the shape-null band are described as executed, but `results.json` contains no fields for either. Claims of robustness machinery with no recorded output read as decorative.

### Actionable revisions
- Either implement true reverse-mode autodiff through the rollout and re-run, **or** rename and reframe the method honestly as finite-difference / zeroth-order schedule optimization and remove all "differentiable/backprop/autodiff" language. The current title and acronym are not supportable.
- Replace Table 1 with the *actual* code values ($T=100$, 12 knots, 6→32→32→12 MLP) or re-run at the claimed settings; do not report aspirational hyperparameters.
- Use a genuinely external reference (certified optimum or a published best cut for real G-set) and report it, or explicitly state the pooled-best definition and drop the "removes endogenous bias" claim.
- Add the dt-halving and shape-null outputs to the results, or remove those claims.
